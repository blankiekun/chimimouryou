# Code map

A dense, feature-by-feature map of where things live and how they behave, for agents and contributors. `CLAUDE.md` holds the rules and points here; look a feature up by name (headings and bold names below) before changing it.

## Desktop and standalone editions

- `apps/desktop` (P5): an Electron shell serving the standalone build from `http://127.0.0.1:41917` with Yomitan loaded unmodified (`scripts/fetch-yomitan.sh`, pinned, not committed; `yomitan-shim.cjs` adds `chrome.permissions`); see its README. The Docker images never install it (`.dockerignore`, and web.Dockerfile copies only `apps/web/package.json` before `pnpm install`); Electron's binary is fetched by its `fetch` script, not on install.
- Discord companion (`apps/anki-discord/`, an Anki add-on, BSD-3, standard-library Python, README has install, config and the protocol): browsers can't reach Discord, so every build sends the finished status to this add-on inside Anki Desktop, which forwards it over Discord's local IPC (`ipc.py`: frames are LE u32 op + u32 length + JSON; handshake op 0, `SET_ACTIVITY` op 1; `discord-ipc-0..9` under `$XDG_RUNTIME_DIR`/`$TMPDIR`/`$TMP`/`$TEMP`/`/tmp` plus the flatpak/snap subfolders, `\\?\pipe\discord-ipc-N` on Windows). `server.py` listens on `127.0.0.1:41918` (config `port`; the desktop app has 41917, AnkiConnect 8765): `GET /v1/status`, `PUT /v1/activity`, `DELETE /v1/activity`; only `DEFAULT_ORIGINS` (Pages, desktop) plus config `extraOrigins`, Host must be `127.0.0.1`/`localhost:<port>` (DNS rebinding), preflights answer `Access-Control-Allow-Private-Network`, body ≤ 16 KB, nothing logged. `activity.py` keeps only Discord's fields and clamps them (`type` always 0, `name` overrides the app name, https URLs only, ≤ 2 buttons). `presence.py` coalesces to one update per 15 s (newest wins, first at once), reconnects when Discord restarts (Unix: noticed while idle; Windows pipes: on the next update) and clears on stop. `CLIENT_ID` in `__init__.py` is the "Chimi Reader" Discord app (art asset key `applogo`). `aqt` is imported only in `__init__.py` (profile open/close hooks, work on background threads); tests in `tests/` (CI's Server scripts job) use a fake Discord on a Unix socket. `build.py` makes `chimimouryou-discord.ankiaddon` (gitignored; leaves out `user_files/`). The web side is the `discord` plugin below. Hub relay (`relay.py`, contract: the social hub's presence API): paired with a presence key (`PUT /v1/pair {hub, key}` from the page, https hub and `pk_…` key only, or Tools → "Pair chimimouryou Discord…" in `__init__.py`, a code traded at `POST {hub}/v1/presence/pair` with the name "Anki on <hostname>"; config `hub`), the key and hub are kept in `user_files/pairing.json` (mode 600; Anki keeps `user_files` across updates) and `GET {hub}/v1/presence/current` (Bearer key, no redirects) is polled while paired and Discord is connected (Cloudflare budget: `TIERS`, 30 s, 2 min after 10 min without a hub status, 5 min after 1 h; the hub's `next`, JSON on 200 or `X-Next` on 204/401, when larger; errors back off to 10 min), stopping with the profile; 401 forgets the key. Push (0.3.0): while paired and Discord is connected, `Relay.stream_once` holds `GET {hub}/v1/presence/stream` open with `ws.py` (a minimal RFC 6455 client: Sec-WebSocket-Accept checked, masked frames, text joined from fragments, ping/pong, close, 16 KB cap, binary/extensions refused, no redirects) and stops polling; each message goes through `_apply`, the same path as a poll's 200 (`{"activity": null}` clears), and clears at `expiresAt` itself (wall clock); a text `ping` every 50 s (`STREAM_PING`, Cloudflare drops WebSockets idle 100 s), no pong for 100 s = dead. The relay never sends anything about what this computer reads to the hub.

## Server

- Docker stack (`docker-compose.yml`): `web` (nginx + the built app; `docker/40-ebook-reader.sh` creates `/data` for PUID/PGID, sets the nginx user and renders the nginx template), `account` and `catalog` (services image target `base`), and the optional profiles `import`, `difficulty` and `mokuro`. Paths come from the environment (`/library`, `/data/{sync,accounts,state}`); every setting is in `docs/CONFIGURATION.md`.
- nginx config: `scripts/calibre/nginx-ebook-reader.conf.template` (upstream's `default.conf` plus the Calibre and account locations), rendered by `render-nginx.sh` when the web container starts. Server-level extras (TLS, resolver, real IP) go in `/etc/nginx/ebook-reader.d/`.
- `DATA_PATH` holds everything the server stores: `sync/` (shared WebDAV folder, `/calibre/sync/`), `accounts/<account id>/` (per-account WebDAV, `/account/sync/`), `state/account/accounts.db`, `state/catalog/` (catalog, `no-cover.json`, `thumbs/`: card-sized covers, `/calibre/thumbs/`), `state/import/` (queue, `jobs.json`, `calibre-write.lock`), `state/difficulty/` (results, `frequency-dictionary.zip`, optional `term-dictionaries/`). Account data includes synced AI keys: never put `DATA_PATH` on storage other machines can read.
- Browser storage (settings, cached books, highlights) is per origin, so an HTTP and an HTTPS address of the same server don't share it. Calibre books and their progress, statistics and highlights come back from the server. Over plain HTTP the service worker/offline mode and some File System Access features don't work.

## Features (not upstream)

- Calibre library (`/calibre/catalog.json`, files at `/calibre/library/`, read-only; only book files and covers are served).
  The catalog is built from a copy of `metadata.db` by `build-catalog.py` (the `catalog` service, every `CATALOG_INTERVAL` seconds, only when the DB changed).
- Calibre is the default storage source (`StorageKey.CALIBRE`, `lib/data/storage/handler/calibre-handler.ts`). The Browser source is only offered in builds that default to it (`browserSourceAvailable`, `fallbackStorageSource` in `storage-view.ts`: the reader-only static build); the browser handler stays as every source's IndexedDB cache. Signed out where reads need an account, the catalog's 401 lists an empty library that asks to sign in.
  The library lists the whole catalog. With no books, the manage page says why: a 404 for `catalog.json` (first build still running) sets `libraryBuilding$` and the page refetches every 15 s; an empty catalog offers Import only when the account has `import` and `GET /calibre/import/api/jobs?ids=` answers (`importServiceRunning`; nginx gives 502 when the service is off). An empty `LIBRARY_PATH` the import service may write (owned by its uid) becomes a new Calibre library on its start (`create_empty_library`); a folder with any file in it is never touched.
  Opening a book for the first time downloads it from Calibre, processes it, and uploads the processed data to the server (not for manga: every device loads the CBZ itself).
  Reader data (book data, progress, statistics) syncs through nginx WebDAV at `/calibre/sync/`, with the same folder-per-title layout as GDrive. Sync for Calibre books is always on, regardless of the auto-replication setting.
  Books are identified by title, so the catalog makes duplicate Calibre titles unique by appending ` (author)` or ` [id]`.
  Importing a file into the Calibre source adds it to the Calibre library (accounts with the `import` permission): `lib/data/calibre-import.ts` uploads to `/calibre/import/api/` (`scripts/calibre/import/service.py`), a queue that runs `calibredb add` one book at a time and then rebuilds the catalog. It is the only writer of `metadata.db`; Calibre's own title+author check refuses duplicates. Afterwards the library is refreshed and books whose title names an existing series are offered for it. Admins deleting Calibre books in the library also remove them from it (`removeFromCalibre` → `POST remove`: `calibredb remove`, i.e. Calibre's recycle bin; game folders are deleted). `build-catalog.py` takes a lock (`catalog.json.lock`) and gives `catalog.json` its inputs' mtime, so builds from the timer and the queue don't race.
  Series made by readers (library select mode → "Make series", `book-card/series-dialog.svelte`, `lib/data/series-overrides.ts`, `series` permission) are shared by everyone in `/calibre/sync/series.json`, keyed by title; they override the catalog's series (an empty series removes a book from one) and are applied in `CalibreStorageHandler.getBookList`.
  Calibre books are cached in the browser (IndexedDB) and only re-downloaded when the server copy is newer. The "External Read" hint is skipped for them.
  When the server can't be reached (fetch `TypeError`), `getBookList` lists the cached books instead (`cachedBookList`, `libraryOffline$` → banner with retry in `/manage`, retried on `online`), and `/b` opens a cached book when sync fails (like `/m` and `/v`); failed uploads stay queued and retry on the next save or `online`. Home books (My books + Continue reading, not VNs) are downloaded in the background from `/manage` (`lib/data/offline-books.ts`, own handler instances, one at a time; `saveLocally` uses its own browser handler for the same reason).
  Books without a Calibre cover get one: the catalog builder extracts it from the EPUB into the book's folder as `cover.jpg` (JPEG unchanged, other formats converted at full size; never overwrites; `metadata.db` is not modified, so Calibre's `has_cover` stays unset). Cover detection: OPF cover-image / `meta name=cover` / guide cover page / item named "cover" / first image on the first pages / first manifest image; SVG/XHTML cover pages are followed to their image. EPUBs without a usable one are remembered in `state/catalog/no-cover.json` (raise `COVER_EXTRACTOR_VERSION` to retry them). The builder must run as the library owner (`PUID`).
  The catalog skips non-zip EPUBs, such as macOS `._` resource forks that were imported into Calibre.
  It also carries tags, rating and publisher, and a series for every book: Calibre's own series, or one inferred from volume numbers in titles (`split_volume` in `build-catalog.py`, `seriesInferred: true`).
  `scripts/calibre/assign-series.py` writes such series into Calibre itself (in the `import` container: `docker compose exec import calibre-debug -e /app/assign-series.py -- [--apply]`), using the same title parsing: books without a series join a matching Calibre series (width/case ignored) or, two or more distinct volumes with a common author, form a new one; books by another author (e.g. manga adaptations) are left out. It also merges series that are one work (`merge_plan`, sharing an author): names that differ only in width, case, spaces, punctuation or store tags like 【電子版限定特典付き】 (`merge_key`, letters and digits only; the spelling found in most book titles wins), and series named after one volume (`volume_series`: digits only, not 上/中/下; a misnamed main series keeps its indexes, per-volume part series get N.part, sequels like はやて×ブレード2 stay apart). Store tags are also left out of new series names. Dry run by default; `--apply` copies `metadata.db` to `state/import/backups/` (last 5) and writes through Calibre's API under the import queue's lock; `--json` for machines. Admin panel → Tools → Series runs it through the import service (`POST /calibre/import/api/series`, admins only via nginx `/_account_admin`, `components/admin/series-tool.svelte`).

UI: `audiobook-controls.svelte` (buttons in the bar) and `audiobook-controls-panel.svelte` (speed/options panel below it), runes, state from `controller.state$`. Legacy players must not assign to `controller`'s members at the top level (`controller.x = …` makes Svelte wrap it in a source and breaks method calls): use its methods (`setCues`).
    Without an ElevenLabs voice connection with a key on this device (or with the voice feature set to `deviceVoice`, `'device'`) the AI voice reads with the device's Web Speech voices (`speechSynthesis`, `deviceVoiceName$` per browser, Japanese first, Settings → AI → Voice, `settings-ai-voice.svelte`); `boundary` events give the phrase highlight (`spokenPhrases` + `timelineEntryAt`), and the whole chunk stays lit when a voice sends none. Anki's AI sentence-audio fallback still needs ElevenLabs.
    With one, the AI voice calls ElevenLabs directly from the browser (`elevenLabsVoice()` in `tts.ts`: the key from `aiConnectionKeys$`; `POST <endpoint>/text-to-speech/<voice>/with-timestamps`, `xi-api-key`, the voice feature's model, default `eleven_v4`; voices listed from `/v1/voices` into the connection cache's `voiceList`) in chunks of 200-800 characters with `previous_text`/`next_text`. The character timestamps become a phrase timeline (`readingTimeline` in `data/tts.ts`) that drives the highlight. Audio is cached around the current chunk only (`data/tts-audio-cache.ts`).
  - Selecting text shows a toolbar (`book-reader/selection-toolbar.svelte`): four highlight colours, "Note", and "Ask AI" (`book-reader/ask-ai-panel.svelte`, `lib/data/ask-ai.ts`), which streams from OpenRouter chat completions and has preset buttons (Settings → AI).

  Fast core (`jiten/core.py`, same code in `lib/functions/analysis/core.ts`, parity fixture `tests/fixtures/difficulty-core.json` checked by `test_core.py` and `core.test.ts`; `CORE_VERSION`): Sudachi tokens → `compound_merge.merge_compounds` without the Reader's readings (the word lists' segmentation seam, ported as `mergeCompounds`) → `word_units` → per lemma its count and its best rank over the spellings met (`best_ranks`/`bestRanks`, core version 3: Sudachi's normalized form, often the rare spelling (見付かる 22,806, 見つかる 490), the dictionary form and, for an all-kana form, the best rank of any term read that way, `FrequencyTable.best_by_reading`: すわる takes 座る's; noise as `is_noise_word`, names counted apart; core version 4: a word written in katakana, met at least `KATAKANA_NAME_COUNT` 3 times and ranked past `KATAKANA_NAME_RANK` 50,000 is an untagged name (クーク, ゴジュウカラ: in a 5,000-word children's book a few of them decided V98), so technical katakana terms that rare count as names too)) → `v98` (the top-N words for 98% of the running words, a word met more than `REPEAT_CAP` 10 times counting as learned after 10; null beyond the list) and a log-rank histogram (`hist`/`histTypes`, 4 buckets a decade, the last unranked), plus two facets from the text (`facets`, core version 2): `rubyKanji` (share of the kanji under the author's ruby, from `book_text`'s ruby count; `rubyKanjiCount` over the HTML in the browser) and `sentLen` (mean characters per sentence). Stored on each estimate as `core`; it is the estimate (engine 4), and a library run redoes estimates with an older `core.v` (`needs_estimate`). The facets never change the level: the book page's Difficulty box and the difficulty dialog show "Full furigana" from 50% (`bookFacets`, `fullFuriganaShare`), and beside it the level read with the furigana (`furigana_score`/`coreFuriganaScore`, fixture `furiganaScores`; `withFurigana`, shown when 0.5 or more below): the level less `FURIGANA_DROP` (2) times how far rubyKanji is along `FURIGANA_RAMP` (0.5 → 0.9, so light novels' ruby at 0.3-0.45 never moves it), at least 1, worked out from the stored level and facet (no core version bump); fitted on the 60-work service comparison (fully ruby'd books sat 1.2-2.1 levels above Jiten, LearnNatively and jpdb mapped onto the scale) and checked on ~480 Jiten-matched library books (Spearman +0.63 → +0.71, other books unchanged). Rank gates, the library's level, sorts, filters and Read next stay on the base level and sentence length as short / average / long by the library's tertiles (`sentenceCuts`, 22.3 and 25.9 chars, from 3,000 random library books). The 1-10 book level (`lib/data/difficulty-core.ts`): V98 on the frozen bell-curve scale `jiten/core-scale.json` (copy in `lib/data/difficulty-scale.json`, a test keeps them equal; anchors per quarter step from `distil/core_scale.py` over a 3,000-book reference sample, mean 5.5, SD 2, versioned; version 3 is core version 4's) with a book tier name per whole step (`tiers`, 1 Slime … 10 Demon King; not Reading rank's names). For you: `forYou` from the word list (share known, words to learn to 98%, unknown words per character), `relativeLevel` maps the share to 0-5 (99.5% → 0, 98% → 2, 95% → 3.5, 90% → 5). The Store's Known words sort and Read next take every other book's share from its histogram (`estimatedShares` in `known-words.ts`: a reader knowing the top C words, C fitted to the books with an exact coverage, else the placement cutoff); Read next orders its pool by closeness to 98%. Standalone: the analysis worker's `core` part (Sudachi and `core-frequency.tsv.gz` from build.sh: ranks, reading ranks and compounds, `core_table_text`; no Pyodide) runs ahead of the word list, and the book page shows its level first.
