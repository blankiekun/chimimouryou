# Code map

A dense, feature-by-feature map of where things live and how they behave, for agents and contributors. `CLAUDE.md` holds the rules and points here; look a feature up by name (headings and bold names below) before changing it.

## Desktop and standalone editions

- `apps/desktop` (P5): an Electron shell serving the standalone build from `http://127.0.0.1:41917` with Yomitan loaded unmodified (`scripts/fetch-yomitan.sh`, pinned, not committed; `yomitan-shim.cjs` adds `chrome.permissions`) and, on Linux and Windows, LunaHook + Locale Remulator + the chimihook helper for native play (`scripts/fetch-lunahook.sh`, `games.js`, see Native play); see its README. The Docker images never install it or `apps/android` (`.dockerignore`, and web.Dockerfile copies only `apps/web/package.json` before `pnpm install`); Electron's binary is fetched by its `fetch` script, not on install.
- `apps/android`: a Capacitor 8 shell (package `moe.blankie.chimireader`, never changes) around the standalone build, served from `https://chimimouryou.localhost` (fixed: IndexedDB is per origin); see its README. `MainActivity.java`: Back walks the WebView history, leaves at the root. Safe areas come from Capacitor's SystemBars padding the WebView (no `viewport-fit=cover`). Drive: Google refuses web sign-in in a WebView, so `lib/data/standalone/android-drive.ts` (`nativeDrive()` = `Capacitor.isNativePlatform()`) asks the app's `DriveAuthPlugin.java` (Play services `AuthorizationClient`, `drive.file`, interactive only from a click, else `needsConsent` → "Sign in to Drive again") for a token; expiry from Google's tokeninfo (POST); no refresh token, so `nativeGrant` is kept in its place for `driveSignedIn`/`syncFileStore` and never revoked. `storage-oauth-manager.ts` takes this branch for the default Drive source before any pop-up; `signInToDrive` opens no pop-up there; `isStorageSourceAvailable` offers Drive without a client id. The Android OAuth client must sit in the web client's Google Cloud project. CapacitorHttp stays off. CI (`ci.yml` `android`) uploads a debug APK when its inputs change; `release.yml` `android` signs one with the `ANDROID_KEYSTORE*` secrets after `desktop-release`. Downloads: the WebView drops `<a download>`, so `lib/data/standalone/native-save.ts` (`catchDownloads`, root layout, app only) patches `HTMLAnchorElement.prototype.click` and catches clicked `a[download]` of blob/data URLs, sending them in 3 MB base64 chunks to `FileSavePlugin.java` (`ACTION_CREATE_DOCUMENT`, no permission). `allowBackup="false"` (secret settings live in WebView storage). Icon: vector adaptive icon from the app logo. No Yomitan, folder sync or COOP/COEP in the WebView.
- Discord companion (`apps/anki-discord/`, an Anki add-on, BSD-3, standard-library Python, README has install, config and the protocol): browsers can't reach Discord, so every build sends the finished status to this add-on inside Anki Desktop, which forwards it over Discord's local IPC (`ipc.py`: frames are LE u32 op + u32 length + JSON; handshake op 0, `SET_ACTIVITY` op 1; `discord-ipc-0..9` under `$XDG_RUNTIME_DIR`/`$TMPDIR`/`$TMP`/`$TEMP`/`/tmp` plus the flatpak/snap subfolders, `\\?\pipe\discord-ipc-N` on Windows). `server.py` listens on `127.0.0.1:41918` (config `port`; the desktop app has 41917, AnkiConnect 8765): `GET /v1/status`, `PUT /v1/activity`, `DELETE /v1/activity`; only `DEFAULT_ORIGINS` (Pages, desktop) plus config `extraOrigins`, Host must be `127.0.0.1`/`localhost:<port>` (DNS rebinding), preflights answer `Access-Control-Allow-Private-Network`, body ≤ 16 KB, nothing logged. `activity.py` keeps only Discord's fields and clamps them (`type` always 0, `name` overrides the app name, https URLs only, ≤ 2 buttons). `presence.py` coalesces to one update per 15 s (newest wins, first at once), reconnects when Discord restarts (Unix: noticed while idle; Windows pipes: on the next update) and clears on stop. `CLIENT_ID` in `__init__.py` is the "Chimi Reader" Discord app (art asset key `applogo`). `aqt` is imported only in `__init__.py` (profile open/close hooks, work on background threads); tests in `tests/` (CI's Server scripts job) use a fake Discord on a Unix socket. `build.py` makes `chimimouryou-discord.ankiaddon` (gitignored; leaves out `user_files/`). The web side is the `discord` plugin below. Hub relay (`relay.py`, contract: the social hub's presence API): paired with a presence key (`PUT /v1/pair {hub, key}` from the page, https hub and `pk_…` key only, or Tools → "Pair chimimouryou Discord…" in `__init__.py`, a code traded at `POST {hub}/v1/presence/pair` with the name "Anki on <hostname>"; config `hub`), the key and hub are kept in `user_files/pairing.json` (mode 600; Anki keeps `user_files` across updates) and `GET {hub}/v1/presence/current` (Bearer key, no redirects) is polled while paired and Discord is connected (Cloudflare budget: `TIERS`, 30 s, 2 min after 10 min without a hub status, 5 min after 1 h; the hub's `next`, JSON on 200 or `X-Next` on 204/401, when larger; errors back off to 10 min), stopping with the profile; 401 forgets the key. Push (0.3.0): while paired and Discord is connected, `Relay.stream_once` holds `GET {hub}/v1/presence/stream` open with `ws.py` (a minimal RFC 6455 client: Sec-WebSocket-Accept checked, masked frames, text joined from fragments, ping/pong, close, 16 KB cap, binary/extensions refused, no redirects) and stops polling; each message goes through `_apply`, the same path as a poll's 200 (`{"activity": null}` clears), and clears at `expiresAt` itself (wall clock); a text `ping` every 50 s (`STREAM_PING`, Cloudflare drops WebSockets idle 100 s), no pong for 100 s = dead. ## Server

- Docker stack (`docker-compose.yml`): `web` (nginx + the built app; `docker/40-ebook-reader.sh` creates `/data` for PUID/PGID, sets the nginx user and renders the nginx template), `account` and `catalog` (services image target `base`), and the optional profiles `import`, `difficulty` and `mokuro`. Paths come from the environment (`/library`, `/data/{sync,accounts,state}`); every setting is in `docs/CONFIGURATION.md`.
- v1 API (`server/api/`, service `api`, port 8769; the app's only way to the library and reading data, client in `lib/data/remote/server-api.ts`): `apidb.py` owns `state/api/library.db` (WAL, FTS5 trigram on title/authors/series): `books` (key = Calibre `uuid`, `calibre:<id>` without one, `vn:<folder>` for games; soft-deleted, never removed), account tables (`progress`, `statistics`, `goals`, `highlights`, `book_docs`, `account_docs`, `games`, `game_docs`; account `''` = signed out on a trusted network) and shared ones (`series_overrides`, `book_metadata`). Every row has `modified` (client ms) and `rev` (one `sync_counter`, taken once per transaction); `put_row` writes only a newer `modified` (equal: nothing, no rev; older: 409 with the stored row). `build-catalog.py` upserts `books` when `API_DB` is set (base image) and gives each a sticky `unique_title`: the first build copies today's `unique_titles()`, afterwards a book keeps its title (Calibre title edits too) and a new same-title book gets ` (author)`, then ` [id]`; `catalog.json` keeps its format, takes those titles and gains `bookId` (books.id); it is no longer served, only read by `jiten`, `mokuro` and `import`. `service.py`: `GET version|catalog?since=|books?q=&series=&cursor=&limit=|sync?since=|migration` (the report, admins), `PUT books/{id}/progress|statistics/{date}|highlights/{hid}|docs/{kind}` (book docs: recaps, lorebook, vnsaves, audiobook, subtitles), `DELETE` statistics, highlights and goals (tombstones), `PUT docs/{kind}` (accounts only), `goals/{start}`, `series/{id}`, `metadata/{id}`, `PUT/GET books/{id}/text` (gzipped `{elementHtml, sections, styleSheet}` in `state/api/text/<id>.json.gz`) and `cover` (`state/api/covers/`), `games[/{name}]` (`accounts/<id>/games/<sha256>.zip`), `PUT games/{name}/docs/progress|statistics|vnsaves` (accounts only; a Windows game has no book id, so each is the whole file its sync folder held, newer `modified` wins; read through `sync` as `gameDocs`). nginx: `/api/v1/` behind `_account_shared`, series/metadata/cover behind `_account_series_writes`, games and `books/{id}/text` behind `_account_auth` (text also `limit_req` readings); it passes `X-Account-Id` and the internal token. `migrate.py` copies the WebDAV sync folders in (folders matched by unique title, file names parsed by `syncnames.py`, pinned to `base-handler.ts` by `server/tests/fixtures/sync-file-names.json`); dry run by default, `--apply` runs after every deploy (`deploy.sh`, `ebook-update`) after a catalog build, idempotent, folders untouched, an account folder that is no catalog title is a Windows game: its `bookdata_` record goes to `games`, its `progress_`/`statistics_`/`vnsaves.json` to `game_docs` (shared folders: orphans only); manga and VN folders' records are skipped (no text copy); orphans in `state/api/migrate-report.json` (listed under "Old sync data" in the admin Catalog tool). The first deploy that finds old sync folders and no report stops `web`, builds the catalog with `--force` and migrates before the start; a failure puts the previous images back. Later deploys migrate after the start (what older clients still wrote), failures only logged. Nothing serves or writes the old folders any more; the release after deletes them.
- Shared request layer (`server/httpbase.py`, `COPY` to `/app` in the base image; each service adds its parent folder to `sys.path`): `from_nginx` (internal token), `same_site` (POST Origin: same site, or a bearer over HTTPS from a listed origin or none; account keeps its own sign-in rules), `read_body` (411/413/415, exact length), `send_json`, `guard` (catch-all: logged 500 JSON; import, difficulty, mokuro), `HttpError` (account and import use it as `ApiError`; api subclasses it with `body`), `parse_cors_origins`. Services pass their own settings in, so tests patch them on the service. Request matrix: `scripts/check-service-requests.py` (`nginx BASE USER:PW ADMIN:PW`, `direct` in the difficulty image), diff before and after.
- nginx config: `server/nginx-ebook-reader.conf.template` (upstream's `default.conf` plus the Calibre and account locations), rendered by `render-nginx.sh` when the web container starts. Server-level extras (TLS, resolver, real IP) go in `/etc/nginx/ebook-reader.d/`.
- `DATA_PATH` holds everything the server stores: `state/api/` (`library.db`, text copies, covers, `migrate-report.json`), `accounts/<account id>/games/` (Windows game records), the old sync folders `sync/` and `accounts/<account id>/ttu-reader-data/` (input of the one-time migration, no longer served), `state/account/accounts.db`, `state/catalog/` (catalog, `no-cover.json`, `thumbs/`: card-sized covers, `/calibre/thumbs/`), `state/import/` (queue, `jobs.json`, `calibre-write.lock`), `state/difficulty/` (results, `frequency-dictionary.zip`, optional `term-dictionaries/`). Account data includes synced AI keys: never put `DATA_PATH` on storage other machines can read.
- Browser storage (settings, cached books, highlights) is per origin, so an HTTP and an HTTPS address of the same server don't share it. Calibre books and their progress, statistics and highlights come back from the server. Over plain HTTP the service worker/offline mode and some File System Access features don't work.

## Features (not upstream)

- Calibre library (catalog from `GET /api/v1/catalog`, files at `/calibre/library/`, read-only; only book files and covers are served).
  The catalog is built from a copy of `metadata.db` by `build-catalog.py` (the `catalog` service, every `CATALOG_INTERVAL` seconds, only when the DB changed).
- Calibre is the default storage source (`StorageKey.CALIBRE`, `ServerStorageHandler` in `lib/data/storage/handler/server-handler.ts`, a `BaseStorageHandler`). The Browser source is only offered in builds that default to it (`browserSourceAvailable`, `fallbackStorageSource` in `storage-view.ts`: the reader-only static build); the browser handler stays as every source's IndexedDB cache. Signed out where reads need an account, the catalog's 401 lists an empty library that asks to sign in.
  The library lists the whole catalog. With no books, the manage page says why: a 404 from `GET /api/v1/catalog` (first build still running) sets `libraryBuilding$` and the page refetches every 15 s; an empty catalog offers Import only when the account has `import` and `GET /calibre/import/api/jobs?ids=` answers (`importServiceRunning`; nginx gives 502 when the service is off). An empty `LIBRARY_PATH` the import service may write (owned by its uid) becomes a new Calibre library on its start (`create_empty_library`); a folder with any file in it is never touched.
  Each device downloads a book from Calibre and processes it itself; nothing processed is shared. Only a gzipped text copy (`{elementHtml, sections, styleSheet}`, no images) goes to the server (`PUT /api/v1/books/{id}/text`, best effort) for readings files and estimates; manga and game folders send nothing. A local copy older than the book's `added` time is processed again (`localCopyIsCurrent`: a book imported with an existing title is its new version).
  The catalog and reading data come from `lib/data/remote/server-api.ts`: `GET /api/v1/version` once per page load (an older or newer server is refused with a message), the catalog cached in IndexedDB `chimi-server` and fetched as a delta (`catalog?since=rev`), and a mirror of `GET /api/v1/sync?since=rev` per server and account (`''` signed out; `dropSyncMirrors` when the browser's reader changes). Progress, statistics per day, reading goals, highlights, book docs (recaps, lorebook, VN saves, audiobook position, subtitles), account docs (settings, kanji, words, immersion), Windows game records and their game docs (progress, statistics, VN saves: one whole-file row each, used when the title has a live `games` row and no catalog book; `ServerStorageHandler.gameDoc`) are rows of the account in `library.db`, written row by row (`putRow`; a 409 means the server's row is newer and puts it into the mirror). The replicator asks handlers `getRecentModified(kind)` and `isUpToDate(kind, modified)`; `BaseStorageHandler`'s defaults parse the file names, so Drive, OneDrive and folders are unchanged. `lastBookOpen` ("Last read", Recent) is per account: the progress row's time. Sync for Calibre books is always on, regardless of the auto-replication setting.
  Rows are keyed by the server's book id (`bookId` in the catalog, `bookIdOf(title)`); titles stay unique and sticky (` (author)`, then ` [id]`, see the v1 API above). Books friends sent (not in the catalog) keep their data in the browser. Remove of a Calibre book is local only (the library and the reader's rows stay); a Windows game's record is deleted from the account.
  Importing a file into the Calibre source adds it to the Calibre library (accounts with the `import` permission): `lib/data/remote/calibre-import.ts` uploads to `/calibre/import/api/` (`server/import/service.py`), a queue that runs `calibredb add` one book at a time and then rebuilds the catalog. It is the only writer of `metadata.db`; Calibre's own title+author check refuses duplicates. Afterwards the library is refreshed and books whose title names an existing series are offered for it. Admins deleting Calibre books in the library also remove them from it (`removeFromCalibre` → `POST remove`: `calibredb remove`, i.e. Calibre's recycle bin; game folders are deleted). `build-catalog.py` takes a lock (`catalog.json.lock`) and gives `catalog.json` its inputs' mtime, so builds from the timer and the queue don't race.

- Themes (`lib/data/theme/`, Settings → Themes, guide in `themes.md`) colour the whole app, not just the book: `theme-tokens.ts` lists every colour and its CSS variable, `themes.ts` the built-ins, inheritance and import validation, `theme-style.svelte` applies the active theme to `<html>`.
  Use the CSS variables (e.g. `var(--surface-strong-color)`, `var(--reader-panel-bg)`) rather than fixed colours in components.
- Visual design "Study Book" (the default UI; the full system is `apps/web/DESIGN.md`, sidecar `apps/web/.impeccable/design.json`): a 参考書 look of paper, ink and one green spot colour, flat (no shadows, gradients or pills), square 2px corners, ruled dividers. It ships as the default themes `chimi-light`/`chimi-dark` (Chimi Light / Chimi Dark, `defaultLightThemeId`/`defaultDarkThemeId`); Washi, Sumi and the other built-ins stay selectable and custom themes can recolour everything. BIZ UDPGothic for all chrome (`--app-font-ui`, self-hosted in unicode-range woff2 chunks made by `scripts/fonts/subset-biz-udpgothic.py`, cached on use by the service worker, not precached, like the reader font KZ UDMincho, `uiFontFile`), type scale `--type-*` (Tailwind `text-h1`…), controls 40px (44px on coarse pointers, `--app-control-height`), `SectionHead`/`PointBox` components. Every page and the reader use the shared `app-header` (flat bar; bottom tab bar on phones except in the reader). Settings rows are `SettingsItemGroup` (label left, control right; `wide` stacks); on/off `ButtonToggleGroup`s render as a switch, others as a segmented control, named by the row via context. Shared control styles are `.app-input`, `.app-button` (+ `-primary`/`-quiet`/`-danger`), `.app-switch`, `.app-segmented`, `.app-table` in `app.scss` (`inputClasses`/`buttonClasses` in `css-classes.ts`). Components use theme colours only: CSS variables or the Tailwind colours mapped to them in `tailwind.config.cjs` (`text-danger`, `bg-overlay`…), never palette classes. `themes.test.ts` checks every built-in theme for WCAG AA.
